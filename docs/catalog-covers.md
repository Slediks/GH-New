# Каталог: обложки и прокрутка

## Исправления 10.10.2026

Две причины изменения цветов:

- Карточки по индексу получали `hue-rotate(35deg/-30deg)`. Фильтры удалены.
  Убрано затемнение всей обложки при наведении; кнопка запуска остаётся.
- Сервер уменьшал изображение до 1600 пикселей, переводил в RGB и пересохранял
  в WebP с потерями, без исходного ICC. Теперь Pillow проверяет допустимый формат,
  структуру, декодирование и прежний предел 16 миллионов пикселей. Сохраняются
  точные исходные байты PNG/JPEG/WebP: профиль, прозрачность, EXIF и качество.
  Расширение определяется по содержимому, имя генерируется сервером.

Выдача `/api/covers/<name>` задаёт MIME явно, в том числе WebP на Windows,
и сохраняет `nosniff`. Пропорции изображения не растягиваются: прежний
`object-fit: cover` и размер карточки сохранены. Новых мобильных стилей нет.

**Старые файлы:** удаление CSS-фильтра действует и на существующие карточки.
Однако утраченные при старой конвертации профиль, прозрачность и детали
автоматически восстановить нельзя — для них нужно загрузить оригинал повторно.

## Лимит и обновление

- Общий источник: `shared/config.py`, `MAX_COVER_MB=20` и настройка
  `rules.cover_limit_mb`. МБ в интерфейсе — 1024² байт.
- Администратор может установить 1–20 МБ. Форма автора получает действующий
  предел через авторизованный `GET /api/games/upload-limits`, а не хранит копию.
- Проверка при выборе и перед отправкой показывает «Максимальный размер
  обложки — … МБ.». Сервер повторяет проверку независимо от клиента.
- Общий предел запроса Flask/nginx — 41 МБ: HTML 20 + обложка 20 + multipart.
- Миграция `c4912a780008` повышает прежнее значение 2 до 20, не меняя остальные
  настройки. Ранее явно сниженный предел 1 МБ сохраняется. Пустая база получает
  новый предел из общих значений по умолчанию.

Для обновления требуются новые образы frontend/backend и `alembic upgrade head`.
Существующие файлы обложек не переписываются; новых внешних ресурсов нет.
Проверочное развёртывание — `127.0.0.1:18080`; основной сервер 8080 не обновлялся.

## Навигация

`frontend/src/app/RouteScroll.tsx` подключён один раз рядом с BrowserRouter.
Новая основная страница открывается сверху без плавного перемещения.
Back/Forward восстанавливают координаты записи истории; при асинхронной
загрузке механизм ждёт появления достаточной высоты страницы. Якорь ищется
после появления содержимого. Изменение только query сохраняет позицию.
Ручная прокрутка/клик/клавиша отменяют ожидание восстановления, чтобы страница
не перетягивала пользователя обратно. Позиции ограничены 100 записями и
сохраняются в sessionStorage при уходе из документа; недоступное хранилище
не мешает навигации. Идентификатор включает URL, чтобы начальные ключи
`default` разных документов не смешивались.

## Проверки

- `test_cover_uploads.py` и `test_games.py`: 11 успешных проверок. Сверены
  байты файла на upload → storage → serving для трёх форматов с ICC;
  прозрачность сохраняется вместе с байтами. Проверены ровно 20 МБ,
  20 МБ + 1 байт, совместная отправка HTML/обложки, повреждённые изображения,
  запрещённый формат, лимит пикселей, миграция, права и настройки.
- Playwright проверяет три формата в реальных карточках, отсутствие фильтров
  и затемнения, загрузку двух файлов по 20 МБ через nginx, ошибку формы без
  отправки, переход из нижней части каталога, Back/Forward и отложенный якорь.
  Для длинного каталога используются фикстуры списка; файлы реально загружаются
  на изолированный сервер. Созданные проверочные игры остаются черновиками.
- Первый браузерный прогон не дождался 20-МБ изображения за 5 секунд;
  отдельное ожидание загрузки изображения увеличено до 15 секунд, повтор прошёл.
- Итог: оба браузерных сценария прошли отдельными прогонами. Загрузка и цвета —
  1 passed (18,5 секунды); окончательная навигация 11.10.2026 — 1 passed
  (10,3 секунды). TypeScript, ESLint, Ruff и Docker-сборки прошли.
  На стенде подтверждена миграция `c4912a780008`; сохранённого переопределения
  `settings.rules` нет, поэтому используется общий предел 20 МБ, проверенный API.

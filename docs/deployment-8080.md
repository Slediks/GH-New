- `database.dump` — PostgreSQL custom dump, 1 039 399 байт;
- `game-files.tar.gz` — содержимое тома игр и обложек, 320 211 байт;

Каталог исключён из Git и Docker build context. Для отката схемы использовать
эту копию вместе с прежними образами `2.0`; одно переключение тега не откатывает БД.

До и сразу после миграций совпали: 107 пользователей, 13 игр, 107 кошельков,
сумма балансов 1 001 076 420 сотых очка. Сохранены тома `gamehub_postgres_data`
и `gamehub_game_files`. Инициализированы 6 общих комнат и 66 игровых столов казино.

## Проверка и удаление старого стенда

Браузерная проверка `e2e/deployment.spec.ts`, desktop: **1 passed (7,1 секунды)**.
Проверены вход существующего администратора, каталог, запуск «Змейки» в
изолированном iframe через `/play/`, казино, столы шахмат с коэффициентами,
футбол и форма обложки 20 МБ. Ставки и обмены не выполнялись; ошибок JavaScript нет.

После успешной проверки удалён `gamehub-casino-check`: контейнеры, сеть,
два именованных тома с его отдельной базой и файлами, теги `casino-check`.
Удалён `deploy/compose.casino-check.yaml`. Текущие образы `3.0.2` сохранены.

## Дальнейшая работа

Использовать только существующий `gamehub` на `http://localhost:8080`
или `http://IP:8080` из LAN. Не создавать отдельные стенды без нового указания.
Браузерные проверки и нагрузочные скрипты переключены на 8080;
`TEST_URL=http://127.0.0.1:8080`, проект Playwright — `desktop`.
Проверочные данные создавать осмысленно: база не пустая, её очистка не разрешена.
Старые отчёты со ссылками на 18080 являются историей.

Офлайн-архив 3.0.1 не пересобирался в рамках переноса. Для передачи актуальной
версии другой машине подготовить новый комплект скриптом `prepare-offline.ps1`.

# Plinko: групповые запуски

## Изменения

Вместо одного шарика пользователь может запустить от 1 до 20 одновременно. Ввод суммы относится к **одному шарику**. Перед кнопкой запуска показаны количество, ставка и общая стоимость. При 3 × 10 списываются 30 шейкелей. Действующий максимальный лимит Plinko ограничивает **сумму всей группы**; минимальная ставка применяется к каждому шарику.

Коэффициенты всех 13 ячеек постоянно видны под полем до ставки. Они берутся из серверной конфигурации выбранного риска; для сохранённого результата — из зафиксированных правил его раунда. На поле коэффициенты округляются для читаемости до трёх знаков, точная дробь доступна в подсказке ячейки и правилах. Это округление надписей не участвует в выплатах.

Каждый шарик имеет отдельные траекторию, ячейку, коэффициент и выплату. Все начинают движение вместе, длительность немного различается. Результат шарика появляется после его приземления; окончательный итог — после последнего. Новая группа недоступна до завершения анимации. Режим уменьшения движения показывает сохранённый результат сразу.

## Деньги и сохранение

- `options.balls` — целое количество, по умолчанию 1. Пределы определены в `backend/app/casino/games/plinko.py` (`MIN_BALLS`, `MAX_BALLS`) и опубликованы в `rules.ball_count`.
- Один `CasinoRound`, одна `CasinoSeat` с полной суммой группы и общие операции журнала по идентификатору раунда. В `state.balls` сохранены дочерние результаты: `id`, `stake`, `path`, `bin`, `multiplier`, `payout`. Все суммы — целые сотые шейкеля. Дополнительно сохраняются `count`, `stake_per_ball`, `total_stake`, суммарный `payout`.
- Проверка средств, резерв, расчёт всех шариков, списание и выплата выполняются в существующей транзакции PostgreSQL с блокировкой кошелька. Нехватка средств отклоняет весь запрос; частичных запусков нет.
- Существующий `request_id` и сохранённый `CasinoAction` обеспечивают повтор ответа без нового списания. Ключ с изменёнными параметрами отклоняется. Параллельные разные запросы расходуют только доступные средства.
- Сервер завершает запуск до ответа. Обновление/закрытие страницы не отменяет его и не порождает новую выплату. История `/api/casino/rounds` и получение раунда по ID содержат все дочерние результаты. Журнал кошелька по-прежнему показывает общие операции группы.

Новые таблицы и миграции не нужны: расширено существующее JSON-состояние раунда. Старые одиночные состояния `path/bin` читаются без изменения; новый одиночный запуск дополнительно сохраняет эти поля для совместимости. Версия движка Plinko повышена с 1 до 2; исторические документы правил остаются прежними. Общая версия административной конфигурации и версия движка — разные значения.

## Математика

Модель не менялась: 12 независимых честных шагов, вероятность ячейки k равна C(12,k)/4096. Прежние три таблицы весов и нормализация по административному `return_bps` сохранены. По умолчанию теоретическая отдача до округления — 97%. Каждый шарик рассчитывается отдельно с точным `Fraction`; выплата округляется вниз до сотых, затем целые выплаты суммируются. Это сумма независимых прежних ставок, без изменения шансов и без общего округления всей группы.

Frontend использует `BigInt` для предварительной стоимости. Отображение денежных итогов складывает сохранённые серверные суммы в сотых; браузер не рассчитывает выигрыш по коэффициентам.

## Структура интерфейса

`GameRoom.tsx` сохраняет общий механизм API, идемпотентного повтора и состояния запуска. Модуль `plinko/model.ts` содержит тип шарика, адаптер старых раундов и точный предпросмотр стоимости; `motion.ts` — геометрию и отдельный кадр каждого шарика; `useBalls.ts` — часы анимации и reduced-motion; `PlinkoScene.tsx` — поле, коэффициенты и дочерние результаты. Геометрия не влияет на расчёт выплаты.

## Проверки

- 12 серверных тестов прошли, включая PostgreSQL: независимые исходы, дробные ставки, неверные количества, недостаточный баланс, лимит группы, сохранение, повторное получение результата, запрет второй выплаты. Восемь одновременных запросов с одним ключом создают один раунд; при разных ключах остаток не расходуется дважды.
- Четыре frontend-теста прошли: точная стоимость, старые состояния, одновременное движение двадцати шариков и попадание всех 4096 возможных траекторий в правильную ячейку.
- Desktop Playwright: отказ 5 × 10 при балансе 40; запуск 3 × 10; двойной клик; сверка баланса и повтора запроса; 20 × 1,01; обновление во время анимации; reduced-motion; коэффициенты всех рисков из API; отсутствие горизонтального переполнения на 1440 и 1280; светлая тема.
- Проверки типов, ESLint, Ruff и Docker-сборки прошли. Изолированный стенд: `http://127.0.0.1:18080/casino/plinko`. Рабочий сервер на 8080 и существующие офлайн-архивы этим обновлением не заменялись.

Снимки: группа из трёх, двадцать результатов, светлая тема.

Изменения ограничены Plinko и его подключением к общему запуску. Новая мобильная адаптация не разрабатывалась. Полный повтор проверок всех остальных игр и нагрузочный прогон 100 игроков в рамках этой точечной задачи не выполнялись.

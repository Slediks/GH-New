# Один адрес HTTP в изолированной сети

Публичный адрес — `http://<IP-сервера>:<GAMEHUB_PORT>`. В Compose опубликован
только nginx: `0.0.0.0:${GAMEHUB_PORT}:80`. IP не входит в конфигурацию приложения.
`/api/` проксируется во Flask, `/socket.io/` — в тот же Flask с Upgrade для ws://,
`/play/` — во внутренний статический games. Имена backend/games/postgres/redis
разрешаются встроенной сетью Docker, клиентскому DNS они не нужны.

## Границы доверия

- Основная страница имеет свою CSP: script-src self, connect-src self и WebSocket
  фактического Host:PORT, frame-src self. Для игр не включается unsafe-inline
  в script-src приложения и не разрешаются произвольные внешние iframe.
- Игровой документ имеет отдельную HTTP CSP `sandbox allow-scripts`. Нет
  allow-same-origin, top-navigation, popups, forms или downloads. Браузер создаёт
  непрозрачный origin: parent DOM, cookies, localStorage и аккаунт недоступны.
- Разрешены встроенные скрипты/стили и изображения, аудио, видео через data/blob;
  шрифты — data. Fetch/XHR/WebSocket/Beacon запрещены connect-src none,
  внешние скрипты и ресурсы запрещены default-src none, вложенные iframe,
  workers, object, base и отправка форм запрещены отдельно.
- CSP приходит от сервера, поэтому её нельзя ослабить метатегом внутри игры.
  Игровой ответ не кешируется, не устанавливает cookies и не отправляет Referrer.
  Перед внутренним сервисом удаляются Cookie и Authorization. Начальная
  навигация на общем хосте может отправлять cookie внешнему nginx; это не даёт
  JavaScript игры доступ к cookie и не используется для авторизации файла.
- URL файла содержит подписанное разрешение на конкретный файл и действующую
  серверную сессию, срок 5 минут. Без разрешения и после logout файл не выдаётся.
  Прямой запрос с Sec-Fetch-Dest=document получает 403. Если Fetch Metadata нет
  (возможно на обычном HTTP по LAN IP), валидное разрешение может открыть документ,
  но **HTTP sandbox/CSP остаются действующими**. Защита не зависит от iframe.
- API не выставляет wildcard/null CORS. POST/PUT/DELETE требуют серверный CSRF;
  присутствующий Origin обязан совпадать со scheme + Host + port запроса.
  Nginx сохраняет публичный Host вместе с портом и удаляет подставленные forwarded
  host/proto. Socket.IO использует штатную проверку того же origin, не `*`.
- postMessage принимается только от текущего iframe.contentWindow, с двумя
  строковыми полями type=`gamehub:input` и session текущего запуска. Origin=null
  сам по себе не разрешает сообщения. Сообщение сигнализирует активность,
  а не назначает очки: время, аренда и начисления рассчитываются сервером.

Cookie сессии: HttpOnly, SameSite=Lax, host-only, без обязательного Secure.
Авторизация по-прежнему передаёт только логин на настроенный AUTH_URL согласно
контракту. Проверка IP пользователей не добавлена.

## Ограничения автономных игр

Игра должна быть одним HTML с встроенными ресурсами. CDN, относительные отдельные
JS/CSS/изображения, сетевые таблицы рекордов, workers, eval/Function и постоянное
хранилище из игры не поддерживаются этой политикой. Сохранение прогресса возможно
только через отдельно согласованный серверный протокол, которого сейчас нет.
Полноэкранный режим запускает родительская страница. CSP не является сетевым
файрволом всего браузера: она ограничивает документ и его ресурсы; попытки
самонавигации iframe наружу дополнительно ограничены frame-src self родителя.
На прямой sandbox-странице нельзя считать полностью запрещённой любую навигацию
самой вкладки; доступа к аккаунту это не даёт. Для гарантированного запрета
всего исходящего трафика браузера нужна политика среды, приложение её не меняет.

## Короткая ручная приёмка без автоматических тестов

1. На сервере импортировать готовые образы, заполнить .env, выполнить
   `docker compose up -d`. На другом компьютере открыть `http://IP:PORT`.
2. Войти через существующий локальный API. Обновить страницу: сессия сохраняется.
   В DevTools убедиться, что gh_session — HttpOnly/SameSite=Lax, не Secure,
   без Domain; в запросах нет другого публичного origin и внешних ресурсов.
3. Запустить демоигру: файл `/play/...`, встроенные ресурсы загружаются.
   У iframe только sandbox=allow-scripts. Попытки чтения parent.document,
   document.cookie/localStorage и fetch к /api/profile из игры блокируются.
4. Открыть игровой URL отдельно: при Fetch Metadata — 403, иначе документ обязан
   сохранить HTTP sandbox/CSP и недоступность DOM/cookies/API. URL без ticket
   всегда должен вернуть 403. После logout прежнее разрешение тоже недействительно.
5. На двух компьютерах открыть футбол: одинаковые матч, счёт и события; ws://IP:PORT
   либо same-origin polling. Сделать разрешённую ставку до начала и дождаться
   серверного изменения баланса. Проверить активность и её паузу в фоновой вкладке.
6. На безопасной границе матчей сменить GAMEHUB_PORT и повторить `docker compose up -d`.
   Открыть новый порт без изменения кода/DNS/hosts. Убедиться, что старый порт
   больше не опубликован, а в backend нет ошибок Origin из-за потери порта.

Эти пункты — инструкция приёмки, не утверждение о выполненных проверках.
Состояние фактической поставки описано в [delivery.md](delivery.md).

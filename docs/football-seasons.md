# Football 3.0 — сезоны и футболисты

Дата наполнения: **11 октября 2026 года**. Установка: существующий Compose
`gamehub`, HTTP `IP:8080`; версия образов 3.1.0. Новых стендов нет.

## Что изменилось

| До | После |
|---|---|
| 12 вымышленных команд, сила из восьми командных чисел | 36 клубов, отдельные футболисты и 22 персональные характеристики |
| Пять обезличенных номеров | Сохранён формат 5×5; номер, имя, позиция, усталость и карточка конкретного игрока |
| Бесконечный перемешанный круговой календарь | Сезоны: восемь туров, стыки, 1/8, четвертьфиналы, полуфиналы, финал |

| Нет замен и дисквалификаций | Контекстные фолы, две жёлтые/прямая красная, до трёх замен, сезонные пропуски |

Исторические матчи, принятые ставки, журнал кошелька, авторизация, казино и
HTML-игры сохранены. Неоткрытые старые фикстуры помечены отменёнными;
вымышленные команды неактивны. Движки 1.0 и 2.0 оставлены только для их
замороженных матчей. Текущие сезоны используют 3.0.

## Открытые источники составов

Исходный локальный файл — `backend/data/football-2026-27.json`: 36 клубов,
1 268 футболистов, включая зарегистрированный список B. Для каждого клуба
сохранена ссылка на официальную страницу UEFA состава; для каждого игрока —
имя, номер, позиционная группа, возраст, число выступлений, опубликованный
показатель голов, отметка списка B. Для вратарей колонка UEFA обозначает
пропущенные голы; она **не используется** для оценки удара или силы вратаря.

- Участники: https://www.uefa.com/uefachampionsleague/clubs/
- Корзины: https://www.uefa.com/uefachampionsleague/news/02a8-21717d0c6cb5-03a9a5ff1552-1000--champions-league-league-phase-draw-pots-confirmed/
- Пример состава: https://www.uefa.com/uefachampionsleague/clubs/52280--arsenal/squad/

Все 36 индивидуальных URL находятся в JSON, поле `clubs[].source`.
Скрейпинг и запросы во внешнюю сеть при запуске приложения отсутствуют.
Изображения эмблем UEFA не копировались: используется прежний локальный щит
GameHub, название и цвета клуба. Цвета — редактируемое оформление GameHub.

### Метод рейтингов и его ограничения

Это **приближённая открытая шкала GameHub**, а не коммерческие рейтинги и не
полная статистическая скаутская модель. `backend/football_seed.py` содержит
всю формулу и явный словарь редакторских поправок для известных специалистов.
Случайные значения при наполнении не используются.

1. База 71 для основного списка и 58 для списка B.
2. За подтверждённые выступления UEFA добавляется по 2, максимум 4. Короткая
   выборка влияет только умеренно; это свидетельство использования игрока,
   а не доказательство его качества.
3. К четырём ключевым навыкам позиции добавляется 7. Возрастная поправка
   влияет на скорость и ускорение: +6 до 27 лет, после 29 лет −2 за год,
   максимум −12. Это грубый общий prior, не измеренная скорость каждого игрока.
4. Полевым: вратарские навыки 25, голы дают до +4 к точности удара.
   Вратарям: точность удара 25, пропущенные голы не превращаются в рейтинг.
5. `SPECIALISTS` вручную уточняет сильные стороны: скорость Мбаппе,
   завершение Холанда/Кейна, видение Эдегора/Педри, оборону Салиба/ван Дейка,
   игру вратарей и т.д. Эти числа — явно редакторская оценка роли,
   не результат формулы xG или утверждение о точной реальной вероятности.

Шкала ограничена 0–100. Все показатели можно независимо изменить в админке.
Большинство состава имеет консервативный позиционный профиль, поэтому это
первоначальное приближение; детальная ручная оценка всех 1 268 игроков
потребует дополнительной скаутской работы. Техническая методика не засоряет
пользовательские экраны.

## Модель и управление составами

`TeamPlayer` расширен без смены первичного ключа. Имя не является ID.
В `attributes` хранится строго проверяемый JSON из 22 целых чисел; форма
администратора показывает отдельное подписанное поле для каждого из них.
`provenance` хранит исходное доказательство и дату. Изменения через админку
пишутся в общий `admin_audit_log` с состоянием до/после.

Панель администратора → **Команды**:

- выбрать клуб, изменить название, короткое имя, оба цвета, ассоциацию,
  корзину, тактику, участие в будущих сезонах;
- «Добавить клуб» создаёт неактивный клуб с постоянным ID;
- «Добавить футболиста» или кнопка существующего игрока открывает форму;
- перевод — выбор другого клуба и свободного номера;
- деактивация/снятие допуска сохраняют историю; физического удаления нет;
- конкурентные сохранения защищены `revision`, конфликт возвращает 409;
- номер 1–99 уникален в клубе, включая деактивированных футболистов. Для
  повторного использования номера сначала перенумеруйте прежнюю запись.

Для нового сезона должны быть ровно 36 активных клубов, по 9 в корзине.
При замене клуба подготовьте его состав, деактивируйте прежнего участника и
активируйте нового. Текущий сезон хранит собственный список участников.
В клубе нужен минимум один доступный GK и четыре полевых; дисквалифицированные
игроки не допускаются даже на скамейку. Недостаточный состав не заменяется
вымышленными игроками: работник сообщает ошибку, администратор исправляет roster.

Seed вставляет каждый клуб только один раз по `source_id`. Повторный запуск
**не перезаписывает административные изменения**. Обновление реальных
трансферов: вручную через формы либо отдельным проверенным импортом, сохраняющим
внутренние ID. Замены JSON и рестарта недостаточно для перезаписи живой базы.

## Стартовый состав и симуляция

`simulation/lineups.py` выбирает GK, DF, MF, MF, FW; для контратак второй DF
вместо одного MF. Оценка — среднее ключевых позиционных навыков, штраф 15 за
неподходящую позицию, детерминированный ID при равенстве. Остальные доступные
игроки — запасные. Вратари не становятся полевыми при подборе состава.

Перед расчётом коэффициентов сохраняется логическая копия состава, скамейки,
характеристик, имён, цветов и тактики. После расчёта повторно проверяется, что
администратор не изменил данные. Ставки открываются только после фиксации
snapshot в `Match.team_snapshot`; дальнейшие правки его не меняют.

Действия используют показатели **действующего игрока**, а не средние
командные параметры: скорость/ускорение/выносливость, точность передачи,
сила/точность удара, отбор/перехват, реакция/позиция/ловля/отражение вратаря,
прессинг/дисциплина в фолах. Остальные показатели участвуют в выборе состава
или оставлены как отдельные навыки для дальнейшего развития AI; не заявляется,
что каждый из 22 уже имеет отдельную физическую модель.

Смена состава происходит при остановке игры, после 42% основного времени,
с интервалом минимум 12% длительности. AI оценивает усталость, предупреждение,
позиционное улучшение и необходимость атаковать при отставании. Максимум 3
замены (административная настройка `max_substitutions`, диапазон 0–4).
Замена не меняет число игроков и не возвращает ранее ушедшего футболиста.

### Фолы, карточки, сезонная статистика

Фол возможен в фактической попытке отбора рядом с носителем мяча. Его риск
зависит от дисциплины, отбора, прессинга, относительной скорости и положения
защитника. Прямая красная возможна в опасном скоростном контакте со спины.
Две жёлтые также удаляют игрока. Удалённые исключаются из AI, контактов,
движения и отображения. Команда с меньшинством оттягивает форму назад.
При удалении GK перчатки получает уже находящийся на поле полевой — лишний
игрок не добавляется. Если остаётся менее двух игроков, компактный матч
завершается техническим поражением с преимуществом соперника минимум в три
мяча. Это опубликованное упрощение GameHub 5×5.

`PlayerSeasonStats`: матчи, старты, голы, удары, сейвы, жёлтые/красные, входы
и выходы. Голевые передачи пока не приписываются: прежний движок не хранит
достоверную цепочку последнего паса. Карточки конкретного матча и счётчики
турнира — разные поля. Две жёлтые, приведшие к удалению, не прибавляются к
накоплению за отдельные предупреждения.

Пропуск после 4-й, 6-й, 8-й и следующих чётных жёлтых; красная — минимум
один следующий матч. Уже отбываемый пропуск уменьшается только при завершении
следующего матча клуба. Перед полуфиналами накопленные жёлтые очищаются,
назначенный пропуск не отменяется. `season_recorded` под блокировкой матча
исключает повторное добавление статистики.

## Сезоны и сетка

`CompetitionSeason` хранит участников/корзины, стадию, фиксированную сетку,
чемпиона и даты. `Match` является календарём и носителем результата; отдельная
таблица с дублирующимися итогами не нужна. Таблица вычисляется по неизменяемым
результатам завершённых матчей лиговой фазы.

Жеребьёвка: направленные паросочетания между корзинами, затем раскраска рёбер
в восемь туров. 144 уникальные встречи, по 18 в туре, один матч клуба в каждом
туре; из каждой корзины один соперник дома и один в гостях. Для исходных данных
соблюдаются запрет своей ассоциации и максимум две встречи с каждой другой.
Поиски ограничены числом попыток/узлов: бесконечных рекурсивных перезапусков нет.
Для изменённого администратором невыполнимого набора возможна явно сохранённая
оговорка `draw_associations_relaxed` в правилах матчей: сохраняются все
структурные ограничения, ослабляются только ассоциации. Ошибка раскладки
повторяет жеребьёвку ограниченное число раз, затем требует исправления данных.

Таблица: 3/1/0, разница, голы, выездные голы, победы, выездные победы,
затем стабильный ID. Последний критерий — упрощение вместо полного набора
клубных коэффициентов/дисциплинарных UEFA tie-breaks; случайной сортировки нет.

1–8 идут в 1/8; 9/10 против 23/24, 11/12 против 21/22, 13/14 против 19/20,
15/16 против 17/18 — стыки. Сеянные проводят второй матч дома. Топ-8 получают
соответствующие пути: 1/2 — победители 15–18, 3/4 — 13–20, 5/6 — 11–22,
7/8 — 9–24. Члены каждой пары верхних мест разводятся по половинам сетки;
после фиксации 1/8 сетка не перетасовывается.

Все пары, кроме финала, двухматчевые; выездной гол не даёт преимущества.
При равенстве суммы после второго матча — дополнительное время 25% основной
длительности, затем сохранённая компактная серия по три удара и до преимущества.
Финал один. После финала чемпион сохраняется, через 20 секунд создаётся новый
сезон из локальных активных клубов с новой жеребьёвкой. Интернет не используется.

## Ставки и восстановление

Индексы исходов для совместимости: 0 = хозяева, 1 = гости, 2 = ничья.
Новые матчи сохраняют `regulation_score` и `regulation_winner` отдельно от
итогового счёта/победителя пары. Только основное время влияет на выплату 1X2.
Для старых матчей с `season_id IS NULL` сохраняется прежняя двухисходная модель.

Monte Carlo: 32 воспроизводимых прогона того же состава/движка, попарное
зеркалирование; независимые от настоящего seed. Частоты трёх исходов сглаживаются
Dirichlet(1,1,1), нормализуются до 10 000. Маржа прежняя: коэффициент в сотых
`950000 // probability`; выплата `amount * odds // 100`. Все денежные операции
целочисленные, по существующему журналу и блокировке `match → wallet`.
32 прогона дают грубую модельную оценку, не точные реальные футбольные шансы.
Нет прежнего искусственного ограничения вероятности победы 25–75%.

Сбой процесса во время эфира: сохранённая ставка возвращается существующей
идемпотентной отменой, матч остаётся в истории, турнир назначает повторную
фикстуру. Это **не продолжение с сохранённого физического тика**. Завершённый
матч, чей результат успел записаться, оплачивается без повтора; статистика
также не удваивается. Ответная встреча не стартует, пока первая не завершена.

## UI и realtime

`FootballPage` по-прежнему владеет одним Socket.IO-соединением. Комментарии
получают ID сохранённого `MatchEvent`; REST и realtime объединяются без
дубликатов. Это события симулятора, не пользовательские сообщения.

`useMatchFullscreen` меняет классы того же DOM-дерева. Canvas, BetPanel и
выбранный футболист не перемонтируются. Выход — кнопка/Esc, фокус удерживается
в слое и возвращается к кнопке. Панель комментариев — правая колонка 260–380 px,
не перекрывающая поле. Canvas сохраняет 1000:640, центрируется с тёмными полосами.
Resize пересчитывает только CSS; новый матч закрывает слой. Панель прогноза
раскрывается отдельно, сохраняя введённую сумму и подтверждение.

Имена рисуются рядом с маркерами с простым разнесением пересечений. Hover
показывает имя/номер/позицию/усталость/ЖК, клик и доступный select закрепляют
наблюдение. При замене ID изменяется, интерполяция не смешивает двух игроков;
удаление не анимируется полётом через поле. Новая мобильная версия не создавалась.

## Ограничения первой версии

- Рейтинги — консервативная роль/возраст/использование плюс явные редакторские
  оценки специалистов; не точная измеренная модель всех навыков каждого игрока.
- Компактные позиции GK/DF/MF/FW; не заявлены точные амплуа каждой фланговой роли.
- Ассисты не выводятся как достоверная статистика.
- Последние UEFA tie-breaks заменены постоянным ID; редкие невыполнимые
  административные конфигурации могут требовать исправления или оговорки по странам.
- При аварии активной симуляции — возврат и переигровка, не сохранение каждого тика.
- История выбора сезонов в интерфейсе показывает последние 50; старые сезоны
  сохранены и доступны по API с `season_id`.
- Старый офлайн-архив 3.0.1 не пересобран; новые образы 3.1.0 уже локальны.

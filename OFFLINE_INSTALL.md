# GameHub без интернета: установка

Поставка рассчитана на **Linux-контейнеры linux/amd64** и Docker с Compose v2. На целевой машине не нужны Git, Node.js, Python, npm или pip. Распакуйте весь каталог `gamehub-offline-<version>` на диск; не переносите один архив образов отдельно от исходников и каталога `offline/`.

## Windows (PowerShell)

В каталоге поставки выполните:

```powershell
.\scripts\offline.ps1 install
```

Команда проверяет SHA-256 файлов поставки, импортирует семь локальных образов, создаёт `.env` со случайными секретами, запускает PostgreSQL и Redis, применяет миграции, запускает приложения и проверяет здоровье сервисов. При сбое миграции новые приложения не запускаются. Повторный `install` сохраняет существующий `.env` и тома.

Откройте `http://IP-компьютера:8080`. Порт можно изменить в `.env` до запуска. Нужен свободный порт 8080 и достаточно места для образов, сборок, БД и резервных копий (рекомендуется 10 ГБ свободного места).

На Linux те же операции доступны через `bash scripts/offline.sh install`, а затем `start`, `stop`, `status`, `logs` и `check`. Для чистой проверки выполните `bash scripts/offline.sh check`.

## Вход пользователей

GameHub сохраняет прежний API авторизации. Укажите в `.env` `AUTH_ADAPTER`, `AUTH_URL`, `AUTH_CONTRACT` и, если нужны, `AUTH_HEADERS` по [описанию контракта](docs/auth.md). Этот API должен быть доступен **внутри изолированной локальной сети**. Поставка не создаёт новый сервис учётных записей и не подключается к публичному сервису. При `AUTH_ADAPTER=unconfigured` интерфейс доступен, вход не работает.

Если API использует адрес локальной машины, помните: `localhost` внутри backend-контейнера означает сам контейнер. Используйте доступный контейнеру адрес API в LAN.

## Проверка без сети

Отключите интернет у целевой машины до запуска `install`. `compose.yaml` содержит `pull_policy: never`; команды сборки используют `--network none --pull=false`. Проверка с чистой сборкой: `.\scripts\offline.ps1 check -Clean` (не изменяет работающие контейнеры). Отсутствующий образ или пакет вызывает ошибку, а не скачивание.

Команды управления: `.\scripts\offline.ps1 start`, `stop`, `status`, `logs`. Не выполняйте `docker compose down -v`: эта команда удаляет постоянные тома.

Дальнейшая работа: [обновление](OFFLINE_UPDATE.md), [резервирование и восстановление](BACKUP_RESTORE.md), [откат](ROLLBACK.md).

## Что входит в пакет

Исходники frontend, backend, Arena, редактора, миграции, скрипты и локальные ресурсы; npm cache и Python wheelhouse для Windows x64 и Linux/amd64; образы GameHub backend/frontend, Node 22 Alpine, Python 3.11 slim, PostgreSQL 16 Alpine, Redis 7 Alpine и nginx 1.27 Alpine. Список и хеши находятся в `offline/manifest.json` и `offline/dependencies.json`. Секреты, пользователи, БД и загруженные файлы разработчика в дистрибутив не входят.

Для работы с исходниками на хосте после скачивания GH-New Node 22 и Python 3.11 можно установить заранее. Локальные команды установки пакетов и сборки приведены в [README](README.md#offline-development) и [OFFLINE_UPDATE.md](OFFLINE_UPDATE.md). Кэш и wheelhouse входят как в Git-репозиторий, так и в полный офлайн-пакет; Docker-образы не являются единственным источником пакетов.
